What is Sentinel?

DroidNet Sentinel is a network-security toolkit that audits the Wi-Fi networks you own or are authorised to test. It discovers live hosts, fingerprints open services, classifies risk, and tracks how the network changes over time.

The CLI is the operator's surface; this web dashboard is the read-only view of the audit history stored in sentinel.db.

Typical workflow

  1. Connect to the network you want to audit.
  2. Run python main.py scan (one-shot) or python main.py daemon (continuous).
  3. Open this dashboard to review the findings.
  4. Use python main.py hunt to look up known exploits for the services you found.
  5. Use python main.py cve to check the scan against recent CVEs.

Features

Sentinel — Network scan

Discovers live hosts, performs an Nmap-style port scan and stores results in the database.

Daemon mode

Runs Sentinel in the background on a fixed cadence and emits Telegram alerts when something changes.

Hunter

Cross-references the latest scan against the local Exploit-DB index via searchsploit.

CVE Watcher

Fingerprints services and queries the NVD for relevant CVEs published recently.

Spoofer (ARP)

Manual ARP-poisoning tool for cutting access to an IP. Authorised use only.

Deauther (802.11)

Sends 802.11 deauth frames against a target or broadcast. Requires monitor mode and root.

Reading the dashboard

Each card represents one scan of one network. Hosts are coloured by risk and decorated with badges:

  • Network — the SSID or CIDR of the audited segment.
  • Devices — total hosts that responded in this scan.
  • new — host seen for the first time vs the previous scan of the same network.
  • Disappeared — host that was present in the previous scan and is missing now.
  • Port changes — diff of open services between this scan and the previous one (+ added / - removed).

Press Ctrl + F to filter visible cards by IP or by service banner.

Risk levels

Sentinel assigns one risk label per host based on the set of open TCP ports it found:

LabelTriggerWhat it means
CRITICAL FTP / Telnet / SMB / NetBIOS / RDP High-impact service that should not be exposed on a typical home network.
MEDIUM HTTP / HTTP-alt / DNS / SSDP / NFS Service exposed to the LAN. Often expected, but worth a banner check.
LOW Other open ports Open service that did not match the higher tiers. Worth a banner inspection.
MINIMAL No open ports Host is reachable but exposes no services.

API endpoints

All endpoints require an authenticated session and return JSON. Useful for piping into your own tooling.

  • GET /api/reports — every scan stored in the database.
  • GET /api/scan/<id>/diff — diff of one scan against the previous scan of the same network.

Security & ethics

  • Sentinel is an offensive-security tool. Only use it on networks you own or have explicit written authorisation to test.
  • The dashboard is loopback-bound by default. Bind to LAN only behind a TLS proxy (nginx / caddy); credentials travel in plaintext otherwise.
  • Auto-generated passwords are stored at ~/.sentinel/credentials with mode 0600. Override with the SENTINEL_PASS environment variable.
  • Login is rate-limited (5 attempts per minute per IP) and protected by a per-session CSRF token.
